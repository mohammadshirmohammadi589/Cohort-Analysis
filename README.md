# 📊 Cohort Analysis & Customer Segmentation

## Project Overview

This project analyzes customer purchasing behavior, retention, and customer value using transactional data.

The analysis combines **Cohort Analysis**, **Retention Analysis**, **Revenue Analysis**, **RFM Segmentation**, and **K-Means Clustering** to understand how customers behave after their first purchase and how customer groups differ in terms of engagement and revenue.

The main goal is to translate transactional data into actionable business insights that can support customer retention and marketing decisions.

----
## 🎯 Business Questions

This project focuses on the following questions:

* How many customers return after their first purchase?
* How does customer retention change over time?
* Which customer cohorts show stronger retention?
* How does revenue evolve across customer cohorts?
* Which customer segments generate the most revenue?
* Can customers be grouped into meaningful behavioral segments using RFM metrics?

---

## 📂 Dataset

The project uses the **Online Retail II** transactional dataset.

Each row represents a transaction line and contains information such as:

* Customer ID
* Invoice number
* Invoice date
* Product / stock code
* Quantity
* Unit price
* Product description

The dataset is used to analyze customer-level purchasing behavior over time.

---

## 🧹 Data Cleaning

Before performing the analysis, the transactional data was cleaned to make it suitable for customer-level analysis.

The main steps were:

1. Standardizing column names.
2. Converting `InvoiceDate` to datetime.
3. Removing rows with missing values in the fields required for the analysis.
4. Removing duplicate rows.
5. Keeping transactions with positive quantities.
6. Excluding service/non-product rows such as postage and discounts.
7. Creating a `Revenue` column:

```text
Revenue = Quantity × UnitPrice
```

These steps ensure that the analysis is based on valid completed sales transactions.

## 📅 Cohort Analysis

A customer cohort is defined by the **month of the customer's first recorded purchase**.

For example:

```text
Customer A → First purchase: January → Cohort: January
Customer B → First purchase: February → Cohort: February
```

The analysis then tracks each customer's activity relative to their cohort month.

### Cohort Index

The cohort index represents the number of calendar months since the customer's first purchase:

```text
Month 0 → First purchase month
Month 1 → One month after first purchase
Month 2 → Two months after first purchase
...
```

Calendar-month differences are used instead of dividing the number of days by 30.

---

## 📈 Customer Retention

Retention is calculated as the percentage of customers from each cohort who make a purchase in a specific month after acquisition.

```text
Retention Rate =
Customers Active in Month N
/
Customers in Cohort Month 0
× 100
```

The retention matrix makes it possible to identify:

* Early customer drop-off
* Long-term retention patterns
* Strong and weak cohorts
* Changes in customer engagement over time

### Retention Heatmap

The project generates:

`outputs/cohort_retention_heatmap.png`

This visualization provides a quick overview of customer retention across cohorts.

## 💰 Revenue by Cohort

In addition to customer retention, revenue is aggregated by:

* Cohort month
* Months since first purchase

This allows retention and monetary performance to be analyzed together.

A cohort may have fewer customers but still generate significant revenue, so looking at customer count alone would not provide the complete picture.

## 👥 RFM Analysis

RFM analysis is used to understand customer value and purchasing behavior.

### Recency

Number of days since the customer's most recent purchase.

### Frequency

Number of unique invoices associated with the customer.

### Monetary

Total revenue generated by the customer.

The reference date is defined as one day after the latest transaction in the dataset.

---

## ⭐ RFM Scoring

Each RFM dimension is divided into four quartiles.

The scoring direction is:

* Higher Recency score → more recent customer
* Higher Frequency score → more frequent customer
* Higher Monetary score → higher-value customer

The three scores are combined into an overall:

```text
RFM Score = R Score + F Score + M Score
```

Customers are then grouped into interpretable segments:

* Champions
* Loyal Customers
* Potential Loyalists
* At Risk
* Needs Attention

This segmentation makes the analysis easier to translate into business actions.

---

## 📊 Customer Clustering

K-Means clustering is used as an exploratory customer segmentation method.

The clustering is based on:

* Recency
* Frequency
* Monetary

Because RFM variables can be highly skewed, a `log1p` transformation is applied before standardization.

The workflow is:

```text
RFM Features
      ↓
Log Transformation
      ↓
Standardization
      ↓
K-Means Clustering
      ↓
Cluster Interpretation
```

The Elbow Method is used to evaluate different values of K before selecting a practical number of clusters.

Cluster labels themselves do not have business meaning. Therefore, clusters are interpreted using their average Recency, Frequency, and Monetary values.

## 📌 Business Recommendations

The analysis can support several customer-focused actions:

### Retention

Focus on customers during the early stages after their first purchase, where the largest retention decline can be identified.

### High-Value Customers

Champions and Loyal Customers can be targeted for:

* Cross-selling
* Upselling
* Loyalty programs
* Personalized offers

### At-Risk Customers

Customers with historically strong purchasing behavior but weak recency can be considered for reactivation campaigns.

### Cohort Optimization

Cohorts with stronger retention can be analyzed further to understand which acquisition periods, products, or customer characteristics may be associated with better long-term engagement.

---

## ⚠️ Analytical Considerations

This project intentionally does not estimate profit or build a churn prediction model.

Profit analysis would require a reliable profit-margin assumption.

Similarly, a proper churn prediction model should define churn using a **future observation window** rather than using the same variable that defines the target. This avoids target leakage.

The current project therefore focuses on metrics that can be directly supported by the available transaction history.
